# Plán: hodinový monitor webového klienta (AK25)

Datum: 24. 10. 2026. Větev: `claude/monitor`, postavená na `claude/transparency` (PR 10, `nylzo verify-client`). Zdroj pravdy: AK25 a Z2 v design docu („nezávislý monitor z jiné sítě, který každou hodinu stáhne bundle a porovná hash s vydáním“) a D61. Stav: samostatná noční práce na pokyn vlastníka z 24. 10. 2026.

## D68: workflow `monitor`

- Běží každou hodinu na GitHub Actions, tedy v jiné síti a u jiného poskytovatele než veřejná instance, a ručně přes „Run workflow“. Bez proměnné repozitáře `NYLZO_MONITOR_URL` nic nedělá.
- Z `/.well-known/nylzo/client.json` zjistí verzi serveru. Když to není verze vydání, skončí chybou bez opakování toho, co server poslal, protože text ze serveru nesmí do logu ani do výstupů kroku.
- Stáhne z vydání téže verze `checksums.txt`, jeho podpis a archiv pro linux/amd64, ověří podpis přes `cosign verify-blob` s identitou workflow vydání a tagu, ověří archiv proti `checksums.txt` a z archivu spustí `nylzo verify-client`. Monitor tak porovnává s vydáním, ne s tím, co tvrdí server.
- Server si verzi vybírá sám, takže by mohl tvrdit starší podepsané vydání a posílat jeho klienta i s chybami, které novější vydání opravilo. Monitor proto selže, když server běží na starší verzi, než je poslední vydání, a to vydání je venku déle než den; den je rezerva na nasazení.
- Výstup `verify-client` běží za `::stop-commands::` s náhodným tokenem, takže ani text, který by se do něj dostal ze serveru, nemůže GitHubu poslat příkaz workflow.
- Hlavičky, které přidává proxy nebo CDN před instancí, povolí proměnná `NYLZO_MONITOR_ALLOW_HEADERS` (názvy oddělené mezerou); hlavičky, které mění chování stránky, povolit nejdou (D61).
- Neúspěšný běh je alarm: GitHub pošle e-mail tomu, kdo naposledy změnil plán workflow. GitHub naplánované workflow ve veřejném repozitáři vypne po 60 dnech bez aktivity; pak je potřeba ho znovu zapnout.

Co monitor neumí, platí stejně jako u `verify-client`: server ho může poznat a posílat prohlížečům něco jiného. Odhalí záměnu, která se monitoru nevyhýbá, třeba z napadeného sestavení nebo chybného nasazení, a to do hodiny.

Na vlastníkovi: nastavit `NYLZO_MONITOR_URL` po nasazení veřejné instance a ověřit, že e-maily o selhaných bězích chodí.
